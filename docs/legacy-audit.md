# Legacy project audit

This document is the immutable baseline for the SignLab rebuild. It records what
the school project demonstrated, what its artifacts contain, and why its reported
numbers are development evidence rather than a defensible estimate of unseen-signer
performance. The machine-readable snapshot is
[`docs/legacy/legacy-state.json`](legacy/legacy-state.json), constrained by a closed
[`JSON Schema`](legacy/legacy-state.schema.json).

## Captured state

- **Legacy commit:** `0e630168727e0d526a1f040ce912db26c1cefc72`
- **Commit timestamp:** `2025-12-22T22:37:21-05:00`
- **Branch:** `master`
- **Commit subject:** `Updated live feedback`
- **Tags/remotes:** none were configured
- **Worktree:** tracked files were clean; one untracked local archive was present

The legacy working tree was inspected read-only. No history was rewritten, no tag
was added, and no media, databases, checkpoints, free-form feedback, or absolute
local paths were copied into this repository. The commit and tree hashes are exact
**identification anchors**, not a promise of recovery. No remote, tag, Git bundle,
or durable artifact backup existed during the audit, so recovery is explicitly
recorded as `incomplete-local-only`. Preserved assets can be re-verified only when
an operator supplies the legacy Git and artifact root.

## What existed

The repository had three coupled applications: Streamlit modeler and extractor
frontends plus a PyQt live application. Shared code under `src/core` handled
preprocessing, Keras training, result browsing, live segmentation, feedback, and
SQLite registries.

The external artifact tree was much larger than the source repository:

There were 464 run-registry rows: 457 marked succeeded, six failed, and one still
marked running. The feedback stores contained five sessions, 45 detections, 408
feedback records, and 532 live-evaluation attempts. These counts intentionally omit
record contents because notes and paths may contain private information.

The Git index itself contained 303 files, including 183 compiled `.pyc` files and
only 114 Python source files. Generated bytecode therefore made up most tracked
files and is not migrated.

## Dataset and split reproduction

The reported comparison used 310 preprocessed sequences across five folders:

| Label | Samples |
| --- | ---: |
| hello | 60 |
| no | 71 |
| please | 58 |
| thank you | 53 |
| yes | 68 |

The selected `pos_vel_handscale_smooth_30f` plan centered landmarks at the wrist,
scaled by hand length, smoothed with a three-frame moving average, resampled to 30
frames, added central velocity, and z-scored each sequence.

The training code performed two stratified **sample-level** `train_test_split`
calls with `random_state=42`. Run configuration used 20% test data and 20% total
validation data, producing 186 training, 62 validation, and 62 test sequences.
The manifests had no signer, session, or source-recording grouping key. Samples
from the same person or recording context could therefore cross splits.

## Reported outcomes reproduced

Integer outcomes and macro-F1 values were recomputed from each run's saved test
predictions and confusion matrix rather than inferred from rounded UI percentages.
The public snapshot contains the five-label order and aggregate confusion matrices;
it hashes the source prediction CSV, label map, confusion matrix, metrics file, and
model without exposing sample paths or row-level predictions.

| Displayed family | Correct / test | Test accuracy | Macro-F1 | Status |
| --- | ---: | ---: | ---: | --- |
| Causal GRU | 53 / 62 | 0.8548 | 0.8603 | Historical development result |
| Causal LSTM | 51 / 62 | 0.8226 | 0.8265 | Historical development result |
| Causal TCN | 54 / 62 | 0.8710 | 0.8762 | Historical development result |
| `mamba` | 52 / 62 | 0.8387 | 0.8459 | Misnamed historical development result |

The TCN had the highest saved test outcome, but the four runs reused the same
62-sample test split. The repository also generated calibration plots, embeddings,
confusion matrices, and broad sweep comparisons from test predictions. The split
was therefore repeatedly inspected and cannot serve as a locked final test set.

## Validity and implementation findings

1. **Signer/session leakage risk.** Split membership was random at the sequence
   level; the manifests contained no participant, session, or parent-recording ID.
2. **No untouched final test set.** Test predictions informed model comparison,
   calibration artifacts, embeddings, and result exploration across many runs.
3. **Negative-label mismatch.** Three large negative recordings produced 4,951
   landmark windows under a separate `nothing` tree, while every reported label map
   contained only the five target gestures. Live code expected `nothing`, but the
   compared models could not predict it.
4. **Misleading Mamba name.** The `mamba` branch used stacked dense GELU layers,
   LayerNorm, dropout, and optionally a bidirectional GRU. It did not implement a
   Mamba selective state-space model.
5. **Training-serving drift risk.** Live preprocessing reconstructed behavior from
   saved plan names and settings instead of consuming one immutable, validated
   model bundle shared with training.
6. **Stale machine paths.** Saved resolved configs referenced an earlier absolute
   desktop path, making recovery location-dependent.
7. **Artifact and UI coupling.** Streamlit pages repeatedly discovered and loaded
   large run directories. With more than 16.5 GB in sweep artifacts, result browsing
   became an application performance bottleneck.
8. **Repository hygiene.** Compiled bytecode was committed, while the large private
   data and run stores lived beside application code without a versioned data remote.

## Preserve, migrate, re-create, or retire

| Asset | Decision | Rationale |
| --- | --- | --- |
| Exact Git commit | Preserve by hash | Historical code and behavior reference |
| Four live-imported model files | Preserve hashes; export under #8 | Useful parity and regression candidates, not champions |
| Run summaries, predictions, configs, label maps | Sanitize and index under #8 | Reproduces historical integer outcomes and failure cases |
| Preprocessing plans | Preserve as historical evidence | Inputs for parity tests; not yet portable contracts |
| Feedback and live attempts | Quarantine and sanitize under #8 | Previously inspected development data with privacy risk |
| Raw videos | Do not migrate until consent review | Unknown redistribution/training scope |
| Derived landmarks | Re-create from approved media | Extractor/version provenance is incomplete |
| Sweep checkpoints and old result trees | Retire after compact indexing | High storage cost and invalid selection protocol |
| Streamlit/PyQt application architecture | Retire | Business logic, jobs, and result access were coupled to UI reruns |
| Misnamed Mamba implementation | Retire name; keep behavior fixture | The architecture claim was technically false |

## Integrity and re-verification

The machine-readable snapshot records byte sizes and SHA-256 values for the four
live-imported Keras models and their metric evidence, the preprocessing-plan
registry, live-import registry, run database, feedback database, and live-evaluation
database. Logical paths are relative to an operator-supplied legacy root; the public
snapshot deliberately contains no local absolute path or participant identifier.

The read-only verifier regenerates Git identity, inventory totals, label counts,
database aggregates, run hashes, confusion matrices directly from saved prediction
rows, accuracy, and macro-F1:

```shell
python scripts/verify_legacy_audit.py --legacy-root <legacy-root>
```

The verifier disables optional Git locks and opens SQLite databases in immutable,
query-only mode; it does not write to the old project or emit participant-level
records. It successfully matched the local source inspected for this audit. A
failed or unavailable check means the public snapshot remains identification
evidence only; it must never be described as a durable backup.

These hashes identify the source material for story #8. They do not grant consent,
make the old evaluation valid, or authorize copying private content. Any exported
record must be schema-validated, sanitized, and marked as development evidence.

## Baseline conclusion

The legacy project proved that a local end-to-end gesture prototype and feedback
loop could be built. It did **not** establish unseen-signer generalization,
continuous recognition reliability, calibrated unknown rejection, or faithful
browser portability. SignLab will preserve the prototype's evidence while
re-creating the scientific claims from consent-aware data and grouped evaluation.
